# 第163批：数据库表和字段注释补齐

2026-11-02，v1，责任Skill：code-software-engineer；输入为用户数据库注释补齐要求，基线0f5055f0。
参考已读取工程Skill的开发设计示例与Java规范，按SQL元数据任务裁剪。

## 范围与原则

盘点member/mall/trade当前版本建表及ADD COLUMN脚本、system基础表。只补缺失或空白的中文COMMENT，不替换已有有效注释，不改表名/字段名、类型、默认值、空值、索引、约束、业务数据或API。历史升级脚本保留原位，不为注释重写历史迁移。

字段含义依据现有COMMENT、DO/领域模型、业务代码与现行接口文档；金额注明元/分，状态和业务类型能核实时写明确枚举，无法核实不猜测编码。已退役但仍在初始化中的表只补注释，不借此删除。

## 实施和验收

1. 提供SQL词法扫描和注释目录，覆盖CREATE TABLE及后续ADD COLUMN，列出缺口及来源；处理单行DDL、DECIMAL逗号、嵌套约束、引号和SQL注释。
2. 在原SQL位置补COMMENT，保留既有格式；校验去掉COMMENT后的SQL词法序列与修改前一致，证明无结构变化，并检查缺失数为0。
3. 提供已有库升级工具：默认仅生成计划，读取SHOW CREATE TABLE原始字段定义，保留实际类型/默认值等，只给缺失注释的实际字段生成MODIFY COLUMN及表COMMENT；目录中不存在的历史表/列不猜测。密码仅从环境传给mysql子进程，不写输出或参数。
4. 对解析、注释保留、DDL不变及升级定义保真做聚焦验证，运行受影响后端SQL/H2回归；真实MySQL升级与部署单列未执行。
5. 同步需求索引、交付报告和机器证据，不commit/push，不直接连接并修改运行中的库。

依赖Python标准库及现有Maven/MySQL客户端，不新增第三方包。已有库DDL仍需按环境审核并在维护窗口执行；工具不重建表、不执行回滚、不承诺在线DDL无锁。下一接收方为工程验证及用户真实环境验收。
