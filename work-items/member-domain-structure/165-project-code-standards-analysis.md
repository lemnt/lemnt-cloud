## 全项目结构与边界

静态扫描覆盖公共组件及全部服务的2797个Java生产文件、70个POM和56个Mapper XML；Java格式处理覆盖3001个生产及测试文件。管理端按现有Prettier/ESLint/TypeScript配置全量检查，小程序覆盖JS/CJS/MJS、JSON、WXSS及38个WXML。

## 已确认并处理的问题

1. **单条角色撤销参数反置。** UserRoleGatewayImpl公开顺序是userId/roleId，原Mapper内部顺序相反，导致错误绑定撤销条件。新增测试先复现user_id绑定10而应为2，再修正内部顺序。其他角色/岗位批量删除的绑定回归保持。
2. **超大整数序列化截断。** BigInteger先longValue再判断JS安全范围，2^64会被截成0，错误输出JSON数字。改为原BigInteger比较；已有Long安全范围、边界字符串契约保留。新增测试先失败后通过。
3. **15处SQL写在Java注解中。** 迁入对应Mapper XML；锁查询显式关闭二级缓存、刷新会话缓存。钱包、充值及会员锁按统一规则检查。实际钱包测试验证同事务重复4次锁会执行4条SQL。
4. **19个Mapper内有68个默认方法及3个私有条件方法。** 查询和条件构造迁到现有GatewayImpl，Mapper只保留BaseMapper与XML声明；不新增通用抽象层。配置唯一键、关联删除等测试改为从真实Gateway边界验证。
5. **HTTP对象与应用对象混用。** 两处Controller改用Req，5个Res中嵌套应用DTO改为Res。新增MetaRes、DictDataPageReq及UserDeptTreeRes；最后一个专门保留旧部门节点空名称、false及空children的原JSON规则。
6. **字典分页缺少HTTP边界默认值和校验。** 对齐其他系统列表的默认页码1、每页10；非正分页返回400。字段、公开路径、R分页rows/total保持。
7. **公开模型说明和命名不齐。** 补齐缺失Schema、HTTP record的Serializable，两个QryExe重命名为QueryExe。注解全路径共255处、68文件统一为显式import和短名，格式工具防止回退。
8. **全量检查存在积累。** 修复BannerPage测试prefer-const，统一既有未格式化前端文件和小程序代码；不关闭规则、不删除测试。当前数据库注释目录同步到98表/1100列，旧目录保留。
9. **规范与入口文档落后。** 根README补会员/商城/交易及小程序，增加根规范和小程序规范，修正管理端ID规范的精度风险。小程序当前接口表改为实际mall/trade前缀，旧状态明确标作历史批次记录。

## 格式与行为验证分开

首轮2996个Java文件格式化前后，用JDK解析后的类型语法树及排序后的导入生成指纹，比对一致。后续Mapper、HTTP边界、授权和大整数改动是明确的结构或行为变更，依靠相应回归验证，不混入“仅格式化”的断言。

WXML只改变标签行缩进；不使用HTML格式化器重排正文和表达式。SQL仅排版的TradeOrderMapper版本另外比较SQL词法及动态XML结构，确保与已测试版本一致。类重命名后进行clean构建，避免旧class残留。

## 自动化规则与限度

`scripts/check_architecture.py`检查实际源码类所在模块和POM边界，不以包名中出现domain就误判旧client契约；还检查领域纯度、HTTP Schema/对象、Mapper默认方法、注解SQL、SQL片段与行锁缓存。`scripts/format_java.py`固定工具版本及校验和，并规范注解短名；`scripts/format_wxml.py`只处理标签行缩进。检查器包含正反例测试。

现有库DDL、历史数量回填、MySQL实际锁行为、真实Dubbo/Redis/MQ/支付渠道、浏览器及微信原生编译/真机仍需单独验收。管理端构建保留既有大包提示；本批未为消除提示修改构建阈值或拆改业务页面。
