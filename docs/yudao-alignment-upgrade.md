# 芋道业务对齐升级说明

本轮只调整业务逻辑，支付、退款及物流真实渠道后续接入。没有执行数据库升级，没有提交代码。

## 新库与存量库

新库按各服务 sql 初始化。存量库不能重跑初始化脚本，先停写、备份并在演练库验证。MySQL DDL 会隐式提交，不能依赖 ROLLBACK 撤销结构变更。

1. 核对实际表名。旧 mall_product/mall_spu 等名称应按现有表逐一映射到 mall_product_sku/mall_product_spu 等；禁止直接套用已停用的旧促销转换脚本。
2. 结算提交回执、放弃标记按 Redis 缓存方案迁移并核对有效期，购物车不再需要加购请求表。旧辅助表备份后归档，先保留数据。
3. 旧促销活动、版本、计数、使用历史及请求表全部归档；已有同名 reward/discount 活动表也必须先归档，并检查外键依赖。随后用当前 V15 初始化三个新的活动业务表。旧整单折扣不能无损转换成 SKU 折扣，不自动迁移或启用活动；管理员依据归档规则重新配置并核对金额。
4. 已采用新商品表名的库，核对字段不存在后执行 mall/sql/upgrade/alignment_business_columns.sql；订单库执行 trade/sql/upgrade/alignment_business_columns.sql。历史订单商品行 pay_amount 保留 NULL，走历史退款分摊逻辑。
5. 会员表如存在 member_no 且为 NOT NULL，保留历史值并先改为可空，取消依赖后再归档删除；新代码仅使用主键 ID。member/sql/upgrade/alignment_member_id.sql 仅适用旧版 VARCHAR(40) 定义，实际定义不同需保留原类型调整。
6. 核对券模板 take_type 已包含原公开领券配置，再归档旧配置表。仅移除已退役页面/操作的权限关联，保留仍使用的查询与售后权限；不自动给角色授权。
7. 对结算抵扣、支付权益、部分退款库存回补、整单退券和同售后单重复执行进行验收，再切换新代码。渠道未接入时不能把调用失败视为交易成功。

跨库迁移模板仅复制购物车和券事实；促销保留源数据人工核对。模板事务默认不提交，核对后由实施人员决定提交或回滚。

## 本轮功能收敛

满减按金额/数量阶梯及适用商品范围建模；折扣按 SKU 减价或折扣比例建模。删除自定义草稿发布版本、促销额度账本和请求记录。商品以 SPU 携带完整 SKU 集合保存，移除独立 SKU 写接口、库存调整台账及后台代会员购物入口。

售后退款必须先审核，退货退款必须先确认收货；统一通过售后接口触发退款。行实付金额用于部分退款，积分和经验根据原订单记录回退。同一售后单重试不能重复回补。
