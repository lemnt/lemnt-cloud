# 订单项评价联动

2026-10-29，承接商品评价接口，文章不在迁移范围。

## 创建与状态

会员仍调用 POST `/mall/app/comments`，新增可选 `orderItemId`。新页面必须从本人订单明细读取真实编号，不能使用 SKU 或自行生成编号。`orderNo`、`skuId` 与编号必须匹配。旧请求不传编号时，仅允许该订单内 SKU 唯一定位的真实行。身份取现有网关上下文。

交易服务锁定订单，核验本人、完成状态和明细，再通过私有 ProductCommentClient 保存商城评价。私有接口的订单、商品快照及可创建标记由交易服务生成，不作为 HTTP 入参。商城保存过程中不反查交易，避免持锁循环调用。

订单明细返回 `orderItemId`、`commentStatus`；订单返回 `commentStatus`、`finishTime`。新订单为未评，旧记录未知值保留 NULL；报价没有数据库订单项编号。全部明细确认为已评后更新订单状态、完成时间并写一次33号日志。评价元数据不参与购买快照与下单幂等比较。

## 重试与历史记录

商城保存成功而响应丢失或交易事务失败时，评价不会随交易库回滚。相同会员和完整原内容重试返回原评价编号，修复交易状态；不同内容冲突。完成时间和日志不重复更新。已评价行仍需核验原内容，不能直接伪装重试成功。

旧评价只有在订单 SKU 唯一、原内容匹配且记录未删除时才绑定真实行，不补猜历史评分、会员或商品快照。歧义和逻辑删除旧记录拒绝关联。新评价以真实订单项唯一，允许同 SKU 的不同真实订单行各自评价。

## 数据升级与验证边界

新建库使用现有初始化脚本。旧库先核对备份，再执行 trade 的 `sql/upgrade/order_item_comments.sql` 与 mall 的 `sql/upgrade/order_item_comment_link.sql`；后者新增行编号唯一索引并移除旧订单SKU唯一索引。不得对已初始化新版库重复执行。这里只生成脚本，未执行真实库升级。

双H2数据库测试通过生产组件与进程内RPC适配验证业务事务和失败重试。真实MySQL索引升级、Redis、Dubbo网络、部署HTTP、浏览器和小程序真机仍待验证。自动评价、虚拟评价、批量交互及照片上传仍未完整迁移。

## 自动评价前置字段（2026-10-29）

订单表新增可空receive_time，确认收货时与COMPLETED状态原子写入，并与物流receivedAt使用同一数据库时间。重试保留首次时间，失败随本地事务回滚。旧记录未知保持NULL，未按create_time或finish_time补造。升级脚本trade/sql/upgrade/order_receive_time.sql仅生成未执行。本批未开放自动评价任务；期限、系统空正文保存、日志34与原请求恢复仍待实现，不能将本字段落库视为任务迁移完成。

## 自动评价调度（2026-10-29实现）

启用trade配置 `lemnt.trade.auto-comment.enabled=true`，期限 `lemnt.trade.auto-comment.expire=7d`，间隔 `lemnt.trade.auto-comment.delay-ms=60000`。未启用时不注册调度组件；无需新增HTTP触发接口。使用现有Spring调度器和数据库当前时间，每轮扫描最多50个已完成、comment_status=false且receive_time严格早于期限的订单，逐单持锁复查，单笔失败记录错误并继续。

系统只处理明确false的明细；历史NULL不猜为未评。固定5分、非匿名、空正文、无图片，通过独立私有saveSystem方法保存；HTTP会员入口不能选择该模式。全部明细确认已评后设置finish_time并记录一次34号系统日志，已完成任务不重复执行。商城已保存而响应丢失时，下一轮原系统内容重试复用评价ID并修复交易标记；不能声称跨库全局回滚。会员已评价项不改写。

生产启用和真实RPC网络/定时器部署尚未验收；须先执行既有收货时间升级脚本。上述实现替代上一节“任务尚未实现”的历史状态，历史NULL不自动回填。

## 小程序同页多商品评价

完成订单新增“评价本单商品”入口，进入pages/order-comment/index，仅传orderNo；再次从服务端核验本人完成订单，读取真实订单项ID。同SKU不同订单行分别显示和提交。旧单项入口保留。

顺序调用现有POST评价接口，成功项保留确认状态，失败即停止。结果未知冻结该项原完整内容，重试核验原请求成功后继续余项；明确业务拒绝可修正该项。历史未知状态不猜未评，已评项不重发，缺失或重复行ID拒绝生成表单。换号清空私人内容并拒绝在途旧响应。未永久存储表单或Token。

图片仍填写HTTPS地址，不代表上传已迁移。页面状态和客户端测试不替代真机/部署HTTP验收。

## 评价图片上传（2026-10-29）

单项及整单评价页已增加相册/拍照按钮，使用wx.chooseMedia与wx.uploadFile逐张上传，最多9张，每张10MiB。成功地址回填原图片字段，支持手动删除地址；部分成功保留，失败停止，不自动重发。结果未知评价项禁用图片编辑。上传期间禁止评价提交；换号拒绝旧响应或继续上传。

POST `/files/app/upload`，会员Bearer认证，multipart字段 `file`，返回 `R.data.url`。只接受image/jpeg、image/png、image/webp，验证非空、大小及文件头，存储文件名后缀按验证类型生成。复用system FileUploadCmdExe/FileGateway/OSS，未新增存储系统。非法图片400、缺文件422、缺会员会话由网关拒绝。客户端仅接受HTTPS访问地址。原后台/files/upload身份与行为保留。

部署需将完整/files/app/upload路由至system（不剥离/files/app），配置后端multipart限制允许10MiB文件及请求开销，并配置小程序request/uploadFile合法域名和OSS HTTPS可访问地址。路由配置在外部环境，未发布；未实际写入OSS或进行真机测试。上传失败可能产生未引用文件，不承诺上传全局回滚或自动清理。
